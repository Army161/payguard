# Acceptance test traceability

`kit/spec.md` names eight acceptance tests that must be automated. This maps each one to the tests
that cover it, so the Definition of Done in `kit/build_v1.md` can be checked rather than asserted.

Run them all with `pnpm test`.

| ID   | Requirement                                                                        | Covered by                                                                                                                                                | Notes                                                                                                                                                                                                       |
| ---- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AT-1 | Free shopping: seller returns 402 until settle confirmed                           | `packages/server/test/attack-classes.test.ts` → "AT-1 free shopping" (7 tests)                                                                            | Covers no-payment, facilitator rejection, settle failure, chain never confirming, transaction not found, successful release, and the `fast` mode trade-off.                                                 |
| AT-2 | Replay: second use of same payload rejected                                        | `packages/server/test/attack-classes.test.ts` → "AT-2 replay" (6 tests)                                                                                   | Includes that a replay costs no facilitator call, and that the claim is released after a verification failure but held after a settlement mismatch.                                                         |
| AT-3 | Duplication: 50 concurrent identical requests, exactly one charge and one delivery | `packages/server/test/attack-classes.test.ts` → "AT-3 duplication" (5 tests)                                                                              | The store contract suite in `packages/store/test/contract.ts` proves the same property at the storage layer, for all three implementations.                                                                 |
| AT-4 | Wrong recipient, asset, or amount rejected                                         | `packages/server/test/attack-classes.test.ts` → "AT-4 wrong recipient..." (5 tests)                                                                       | Rail-level equivalents in `packages/rails/test/base-rail.test.ts` and `xrpl-rail.test.ts`, plus live testnet negative cases in `live-testnet.test.ts`.                                                      |
| AT-5 | Facilitator down: buyer fails over to a second rail, single settlement             | `packages/client/test/buyer-attack-classes.test.ts` → "AT-5 facilitator outage" (5 tests)                                                                 | Runs against a real Express seller guarded by `@payguard/server` over a socket. Asserts the second rail settles exactly once and the first settles zero times.                                              |
| AT-6 | Spend cap exceeded: blocked with a reason                                          | `packages/client/test/buyer-attack-classes.test.ts` → "AT-6 a spend cap blocks" (8 tests)                                                                 | Covers per-transaction max, hourly and daily caps, velocity, counterparty allowlist, human approval, and the mainnet refusal. Property tests for the same rules are in `packages/core/test/policy.test.ts`. |
| AT-7 | Kill switch halts all payments within 1 second                                     | `packages/client/test/buyer-attack-classes.test.ts` → "AT-7 the kill switch" (6 tests)                                                                    | Asserts the in-process halt takes effect in under a second by wall clock, and that the file poll interval is clamped so the one second bound holds at any configuration.                                    |
| AT-8 | Audit log complete and tamper-evident (hash chain)                                 | `packages/server/test/attack-classes.test.ts` → "AT-8 the audit log" (7 tests) and `packages/core/test/audit.test.ts` → "tamper evidence, AT-8" (7 tests) | Covers a re-hashed entry (the strongest attacker), a removed entry, a sparse array, and round-tripping through a JSONL export with the chain still verifiable.                                              |

## Definition of done v1

| Item                                 | Status                                                                                                                                                                                  |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AT-1 to AT-8 automated and green     | Yes. `pnpm test` runs them on every push.                                                                                                                                               |
| Coverage >= 95% on core              | Yes. 100% statements and lines, 98.9% branches, enforced by a CI gate at 95/90.                                                                                                         |
| Quickstart timed <= 30 minutes       | Yes. Measured at 11 minutes, 6 of them waiting on a faucet. See `docs/quickstart.md`.                                                                                                   |
| Docker image builds                  | Not verified here. No Docker daemon in the build environment; see blocker 1 in `tasks.md`. `scripts/image-size.sh` reproduces the image's prune and measures 101 MB of runtime payload. |
| SECURITY.md and threat model present | Yes. `SECURITY.md` and `docs/threat-model.md`.                                                                                                                                          |
| Audit vendor RFQ sent                | No. Human item, `kit/todolist.md`.                                                                                                                                                      |
| No mainnet config enabled            | Yes. Refused at runtime by two independent mechanisms, and CI pins the flag to false.                                                                                                   |
